# Week 2 — How to Choose an AI Project (Part 1)

> Course: **AI for Everyone** by Andrew Ng (DeepLearning.AI / Coursera)
> Week: **2 — Building AI Projects** · Lesson: **How to choose an AI project (Part 1)**
> Study notes (original summary, not verbatim transcript).

## Core Idea
Choosing the right AI project is a core leadership skill. The winning intersection is where **technical feasibility** meets **business value** — and the key is to start from a business problem, not from the technology.

## Key Points
- **Two axes every project must satisfy**:
  - **Technical feasibility** — can an ML system actually learn this A→B task with available data?
  - **Business value** — does solving it create meaningful ROI?
- **A "feasible but worthless" trap**: great technology aimed at a problem nobody needs.
- **A "valuable but infeasible" trap**: a dream project the data can't support (e.g., needs reasoning that ML can't yet do).
- **The selection pipeline**: **brainstorm → due diligence → build/run**. Brainstorm many candidate ideas broadly across the company, then screen them, then build.
- **Involve the right people**: pair **AI experts** (who judge feasibility) with **domain/business experts** (who judge value) when screening ideas.
- **Use concrete, measurable value estimates** (e.g., dollars saved, hours reduced) rather than vague "AI will help" claims.
- **Reverse-engineer from business pain**: rather than "we have AI, where can we use it?", ask "which valuable problem could AI plausibly solve?" then check feasibility.
- **Start with quick-to-validate projects** so you learn whether a direction is promising before large investment.

## Takeaways
- The sweet spot = **technically feasible AND business-valuable**.
- Start from the business problem, then evaluate whether data/ML can address it.
- Generate a wide candidate list, then ruthlessly filter.
